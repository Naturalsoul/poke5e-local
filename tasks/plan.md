# Plan: move-coverage

Spec: [SPEC-move-coverage.md](../SPEC-move-coverage.md) · Map: [CAPABILITY-MAP-moves.md](../CAPABILITY-MAP-moves.md)

## Components

1. `tests/move-coverage.test.mjs`: completeness, valid values, builder cross-check, counts summary.
2. `scripts/move-coverage.mjs`: the registry, first generated by a scratchpad seed script, then reviewed by hand.

There's no runtime wiring, so nothing else depends on these files yet.

## Order

1. **Seed and test (vertical slice).** Generate all 830 entries with suggested statuses and write the test. It must pass before any review starts, so every later change is checked by it.
2. **Engine-internal automation.** Hand-mark moves automated inside engines with no builder.
   Candidates from the grep: outrage, magnitude, rollout, dream-eater, struggle, confusion.
   Throw out false positives where the id is just a common word (`fly`, `psychic`, `round`) and
   `held-item-rules`' punch list, which names punch moves for an item, not automation.
3. **Hand review of `plain-damage` suggestions**, alphabetically in about 4 batches of ~50 (option a).
   Any rider moves the entry to `pending` with the right module.
4. **Hand review of `manual` and `other` suggestions** (~84): automatable ones go to `pending: special-mechanics`
   or a better-fitting module; the rest stay `manual` with a reason.
5. **Final check:** `npm test`, `npm run lint`, then the counts summary, then a commit.

Steps 3 and 4 are independent of each other. Both need step 1. Step 2 can run any time after step 1.

## Risks

| Risk | Mitigation |
|---|---|
| A builder returns data that never gets applied. `modifier-effects` defines ~13 moves, but only 4 are in `AUTOMATED_MODIFIER_MOVES`. | In step 1, read how each builder's output is used. If the output isn't applied, that move goes to `pending`, and the test's cross-check uses the narrower set (e.g. `AUTOMATED_MODIFIER_MOVES` for modifiers). |
| Builders need Foundry globals or a specific `move` shape | Use `installFoundryUtils()` from `tests/helpers/foundry-mocks.mjs` and pass the real move objects from `moves.json` |
| The keyword buckets pick the wrong `pending` module | Out of scope here: each later module reclassifies when its spec is written |
| Hand review of ~290 descriptions is long | Batch it into separate tasks, each its own commit-sized step |

## Checkpoints

- After step 1: the test is green, and the counts sum to 830.
- After steps 3 and 4: no unreviewed suggestions remain (the seed marks them with `reviewed: false`, and the test fails while any remain).
- End: `npm test` and `npm run lint` are green.
